# 二秒カメラ（仮）企画書

## 1. 企画概要

ダンスやスポーツなど、何かに夢中になっている人が、撮影を誰かに頼まなくても、自動的に自分の姿を写真に残せるカメラシステムを開発する。

カメラは映像を連続して取得しながら人物の動きをリアルタイムに解析し、人物が一定時間静止したことを検知すると、その前後の映像から静止画を自動で切り出して保存する。

撮影者自身がシャッター操作をしなくても、自分の活動に集中できる新しい撮影体験を目指す。

## 2. 想定する利用者・場面

主な利用者は、自分の活動やパフォーマンスを記録したい人。

利用場面の例：
- 民謡、日本舞踊、ダンスの練習・発表
- スポーツや身体を使ったパフォーマンス
- 一人で練習しているとき
- 撮影を頼める人がいないとき
- 自分の動きやポーズを後から振り返りたいとき

特に、本人が撮影操作を意識せず、活動に集中したまま自然な姿を残せることを重視する。

## 3. 基本コンセプト

**動きを止めた瞬間を、カメラが見つけて撮影する。**

人がシャッターを押すのではなく、カメラ側が人物の動きを解析し、撮影のタイミングを判断する。

## 4. 想定する技術構成

| 項目 | 採用技術・方式 |
|---|---|
| デバイス | iPad mini |
| 動作環境 | Webブラウザ（まずはSafariを想定） |
| カメラ | iPad mini内蔵カメラ |
| 映像取得 | getUserMedia（MediaDevices API） |
| 人物・姿勢解析 | MediaPipe Pose Landmarker |
| 静止判定 | 姿勢ランドマークの位置変化量・時間的な安定度 |
| 静止画抽出 | video要素とCanvas API |
| 保存 | まずは端末内への画像保存を想定 |

専用カメラ機器は使用せず、既存のiPad miniで動作することを目標とする。

## 5. 撮影の仕組み（想定フロー）

1. ブラウザでカメラを起動する。
2. カメラ映像を動画として連続取得する。
3. MediaPipeで人物の姿勢や身体の各部位の位置を解析する。
4. 身体のランドマークの変化量から、人物が静止したかどうかを判定する。
5. 静止状態が約2秒間継続した場合、該当する時間帯の映像から静止画を抽出する。
6. 抽出した写真を自動保存・画面表示する。
7. 再び動き始めたら、次の撮影機会を待つ。

※「静止」は身体が完全に動かない状態ではなく、姿勢の変化が一定の許容範囲内に収まっている状態として扱う。カメラの揺れや小さな自然な動きによる誤検知を抑える必要がある。

## 6. 最初のPOC（概念実証）の開発目標

まずは最小限の機能で、技術的に実現できるかを確認する。

- ブラウザからカメラを起動できる
- カメラ映像を連続取得できる
- MediaPipeで人物の姿勢を認識できる
- 人物の静止状態を検知できる
- 約2秒間静止したら静止画を自動抽出できる
- 抽出した写真を画面に表示できる
- 複数枚の写真を自動的に蓄積できる

## 7. 技術検証で確認すること

- iPad miniのSafariでカメラ取得とMediaPipeが安定して動作するか
- 映像取得と姿勢推定を同時に実行できるか
- 2秒間の静止を適切に判定できるか
- 踊りの途中の一瞬の停止を誤検知しないか
- 撮影された写真が適切なタイミングのフレームになっているか
- 長時間使用しても処理速度や端末の負荷に問題がないか
- カメラ映像や撮影画像を端末内で安全に扱えるか

## 8. 今後の検討・発展構想

- 撮影する静止時間の設定
- 静止判定の感度調整
- 全身・上半身など認識範囲の設定
- 写真の自動整理
- 撮影結果の一覧表示
- 連続撮影の制御
- 静止している間の複数フレームから、よりよいポーズの写真を選ぶ機能

## 9. 開発方針

最初から完成品を目指すのではなく、まずブラウザ上で動作するPOCを制作する。

iPad miniだけで撮影から画像抽出まで実現できるかを検証し、その結果を踏まえて製品化を検討する。

将来的には、一般の人が簡単に利用できるサービスとしての販売を目指す。

## 10. 企画の本質

撮影する人がいなくても、自分の好きなことに夢中になれる。

そして、その時間の中にある自分では気づかなかった素敵な瞬間を、カメラが見つけて残してくれる。

そんな新しい自動撮影の仕組みを実現する。

---

## POC段階での重要な検討事項

「2秒静止した」と判定したときに、静止判定が成立した時点のフレームを保存するのか、静止していた約2秒間の中から最もよい姿勢のフレームを選ぶのかは、初期検証で比較する。

後者は将来的な差別化につながる可能性があるため、発展項目として残す。

## 前提・注意

- ブラウザでのカメラ利用にはHTTPS環境とユーザーによるカメラ許可が必要。
- iPad miniの機種・OS・ブラウザによって性能や対応状況が異なるため、実機検証を行う。
- 本企画書は現時点の構想をまとめたものであり、技術的な実現性はPOCで確認する。
